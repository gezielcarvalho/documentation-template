# Delivery and quality

## Delivery workflow

1. Capture work as a scoped GitHub Issue.
2. Move owner-approved work into progress on the project board.
3. Implement through a pull request with validation evidence.
4. Obtain required review and human acceptance.
5. Treat release/deployment as a separate authorization gate.

## Definition of Ready

- Objective and scope are clear.
- Acceptance criteria are testable.
- Dependencies, risks, and human gates are known.

## Definition of Done

- Acceptance criteria are met.
- Appropriate automated and/or manual validation is recorded.
- Relevant documentation is current.
- Rollback is known, or `Not required` is explained.
- Required review and acceptance have occurred.
